## ログイン/認証の問題

### 「Invalid credentials」と表示される

**原因**: メールアドレスまたはパスワードが間違っている

**解決方法**:
1. 入力したメールアドレスが正しいか確認
2. Caps Lockがオフになっているか確認
3. パスワードをリセット（管理者に依頼）

### 「Session expired」と表示される

**原因**: セッションの有効期限が切れた

**解決方法**:
1. ページをリロード
2. 再ログイン

> セッション有効期限はデフォルトで24時間です。環境変数`SESSION_MAX_AGE`で変更可能です。

### Microsoft認証でエラーが発生する

**原因**: Entra ID設定の問題

**確認項目**:
1. `ENTRA_TENANT_ID`が正しく設定されているか
2. `ENTRA_CLIENT_ID`が正しく設定されているか
3. `ENTRA_REDIRECT_URI`がAzure ADのアプリ登録と一致しているか
4. クライアントシークレットが有効期限切れでないか

**ログ確認**:
```bash
# バックエンドログでエラー詳細を確認
journalctl -u ragtesting-backend | grep -i "auth\|entra"
```

## ファイルアップロードの問題

### 「ファイル形式が正しくありません」(E201)

**原因**: サポートされていないファイル形式

**サポート形式**:
- `.xlsx` (Excel)
- `.xls` (旧Excel)
- `.csv` (CSV)

**解決方法**:
1. ファイルの拡張子を確認
2. Excelで開いて「名前を付けて保存」で.xlsx形式で保存し直す

### 「ファイルサイズが大きすぎます」(E202)

**原因**: ファイルサイズが200MBを超えている

**解決方法**:
1. ファイルを分割する
2. 不要なデータを削除してサイズを減らす
3. 画像や埋め込みオブジェクトを削除

### 「ヘッダーが一致しません」(E203)

**原因**: ファイルの列名が期待される形式と異なる

**解決方法**:
1. テンプレートファイルの列名を確認
2. 列名を正しい名前に修正
3. 列の順序は問わないが、名前は正確に一致させる

**期待されるヘッダー一覧**:
```
GET /excel/config
```
で各ファイルキーの期待ヘッダーを確認できます。

### CSVが文字化けする

**原因**: エンコーディングの問題

**解決方法**:
システムは以下のエンコーディングを自動検出します：
- UTF-8 (BOM付き/なし)
- Shift-JIS / CP932
- EUC-JP

自動検出に失敗する場合：
1. Excelで開いて「名前を付けて保存」
2. 「CSV UTF-8 (コンマ区切り)」を選択

### アップロードが途中で止まる

**原因**: ネットワークの問題またはタイムアウト

**解決方法**:
1. ネットワーク接続を確認
2. ファイルサイズが大きい場合は非同期アップロード (`/upload-async`) を使用
3. サーバーのタイムアウト設定を確認

### 「同一内容のファイルが既にアップロードされています」

**原因**: 重複ファイル検出機能による

**これは正常な動作です**。同じ内容のファイルを再処理する代わりに、既存のデータを再利用します。

**新しいデータとして処理したい場合**:
1. ファイル内容を変更する（日付を更新するなど）
2. 既存のデータセットを削除してから再アップロード

## データ表示の問題

### データが表示されない

**確認項目**:
1. ファイルが正常にアップロードされたか確認
2. データセットのステータスが「ready」か確認
```bash
curl http://localhost:8000/datasets?kind=punches
```

### 検索結果が期待と異なる

**確認項目**:
1. 検索条件が正しいか確認
2. 部分一致/前方一致の違いを確認
   - 従業員名: 部分一致
   - 従業員番号: 前方一致
   - 部署コード: 前方一致

### 残業時間の計算が合わない

**確認項目**:
1. 出退社時刻データが正しくアップロードされているか
2. 時間のフォーマットが「HH:MM」または数値になっているか
3. 基準時間（`BASE_MINUTES`）の設定を確認

## エクスポートの問題

### Excelファイルが開けない

**原因**: ファイルが破損している可能性

**解決方法**:
1. 再度エクスポートを実行
2. 別のブラウザで試す
3. ダウンロードフォルダを確認（ファイルが途中で切れていないか）

### 文字化け

**解決方法**:
1. Excelで開く際に「ファイルを開く」ダイアログでエンコーディングを指定
2. UTF-8を選択

### メモリ不足エラー

**原因**: エクスポートするデータ量が多すぎる

**解決方法**:
1. フィルタで対象を絞り込んでからエクスポート
2. ページネーションを使用
3. サーバーのメモリを増設（本番環境）

## パフォーマンスの問題

### アップロードが遅い

**目安**:
- 1000行: 5-10秒
- 5000行: 20-60秒
- 10000行以上: 数分

**改善方法**:
1. 非同期アップロード (`/upload-async`) を使用
2. ファイルを分割してアップロード

### 画面の表示が遅い

**確認項目**:
1. ブラウザのキャッシュをクリア
2. ネットワーク接続を確認
3. 開発者ツールでボトルネックを特定

### 検索が遅い

**原因**: データ量が多い

**解決方法**:
1. より具体的な検索条件を指定
2. ページサイズを小さくする

## APIエラー

### エラーコード一覧

| コード | 説明 | 対処法 |
|--------|------|--------|
| E101 | 認証エラー | 再ログイン |
| E102 | 権限エラー | 管理者に問い合わせ |
| E103 | セッション期限切れ | 再ログイン |
| E201 | ファイル形式エラー | 対応形式で保存し直す |
| E202 | ファイルサイズ超過 | ファイルを分割 |
| E203 | ヘッダー不一致 | テンプレートを確認 |
| E204 | ファイル処理失敗 | ファイル内容を確認 |
| E301 | ファイル未発見 | 先にアップロード |
| E401 | ジョブ未発見 | ジョブIDを確認 |
| E402 | ジョブ完了済み | 新しいジョブを作成 |
| E501 | バリデーションエラー | リクエスト内容を確認 |
| E901 | レート制限 | しばらく待って再試行 |
| E999 | 内部エラー | ログを確認、管理者に報告 |

### 401 Unauthorized

**原因**: 認証が必要なエンドポイントに未認証でアクセス

**解決方法**:
1. ログインしてからアクセス
2. APIキーが必要な場合は `X-API-Key` ヘッダーを設定

### 403 Forbidden

**原因**: 権限が不足している

**解決方法**:
1. 管理者権限が必要な操作かどうか確認
2. APIキーのスコープを確認

### 429 Too Many Requests

**原因**: レート制限に達した

**解決方法**:
1. しばらく待ってから再試行（1分後）
2. リクエスト頻度を下げる

**レート制限設定**:
- 通常リクエスト: 100回/分
- アップロード: 10回/分

### 500 Internal Server Error

**原因**: サーバー内部エラー

**解決方法**:
1. サーバーログを確認
```bash
journalctl -u ragtesting-backend --since "5 minutes ago"
```
2. 問題が特定できない場合は管理者に報告

## サーバーの問題

### バックエンドが起動しない

**確認項目**:
1. ポート8000が使用されていないか
```bash
lsof -i :8000
```
2. 環境変数が正しく設定されているか
3. データベース接続を確認

### データベース接続エラー

**確認項目**:
1. PostgreSQLが起動しているか
```bash
systemctl status postgresql
```
2. `DATABASE_URL`の設定を確認
3. データベースユーザーの権限を確認

### ディスク容量不足

**確認**:
```bash
df -h
```

**対処**:
1. 古いログファイルを削除
2. 古いデータセットを削除
3. バックアップファイルを外部ストレージに移動

### メモリ不足

**確認**:
```bash
free -h
```

**対処**:
1. 不要なプロセスを停止
2. メモリを増設
3. スワップを追加

## ログの確認方法

### 構造化ログの検索

```bash
# 特定のジョブIDのログを検索
journalctl -u ragtesting-backend | grep "job_id.*abc123"

# エラーログのみ表示
journalctl -u ragtesting-backend | grep -i "error\|exception"

# 特定の時間範囲のログ
journalctl -u ragtesting-backend --since "2026-02-03 10:00" --until "2026-02-03 11:00"
```

### 監査ログの確認

```sql
-- 最新の監査ログを確認
SELECT * FROM audit_logs ORDER BY timestamp DESC LIMIT 100;

-- 特定ユーザーのログイン履歴
SELECT * FROM audit_logs
WHERE action IN ('login_success', 'login_failed')
AND user_email = 'user@example.com'
ORDER BY timestamp DESC;

-- 失敗したログイン試行
SELECT * FROM audit_logs
WHERE action = 'login_failed'
ORDER BY timestamp DESC LIMIT 50;
```
