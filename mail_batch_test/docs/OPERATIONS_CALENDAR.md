# 運用カレンダー

メール一括送信システムの定期運用スケジュールと作業内容をまとめた運用カレンダーです。

## 月次送信スケジュール

### 送信実行日

毎月以下の日程で送信を実施します（営業日の場合）：

| 送信日 | 対象データ | 備考 |
|--------|-----------|------|
| 毎月5日 | 前月末締め | 第1回送信 |
| 毎月15日 | 当月中間 | 第2回送信 |
| 毎月25日 | 当月末見込み | 第3回送信 |

**祝日・休日の場合:** 翌営業日に送信

---

## 送信日の作業フロー（当日実施）

### 1. 事前準備（前日まで）
- [ ] 送信対象Excelファイルが `exports/YYYY-MM-DD/` に配置されていることを確認
- [ ] 宛先マスタ (`data/recipients.xlsx`) が最新であることを確認
- [ ] `.env` の設定が正しいことを確認

### 2. 送信当日（作業時間: 約30分）

**実施時刻:** 9:00〜10:00（業務開始直後）

```bash
# 作業ディレクトリに移動
cd /path/to/mail_batch_test

# 日付を設定（例: 2025-02-05）
DATE=$(date +%Y-%m-%d)

# ステップ1: 送信前チェック
./scripts/check-production-ready.sh $DATE

# ステップ2: 配送計画生成
npx tsx src/cli/plan.ts --date $DATE

# ステップ3: プレビュー確認
npx tsx src/cli/preview.ts --date $DATE

# ステップ4: 送信実行
npx tsx src/cli/send.ts --date $DATE

# ステップ5: 結果確認
cat output/$DATE/send_result.json | jq '.[] | select(.status == "failed")'

# ステップ6: 失敗があれば再送
# npx tsx src/cli/resend.ts --date $DATE

# ステップ7: バックアップ取得
./scripts/backup.sh $DATE
```

### 3. 送信後確認（当日中）
- [ ] 送信成功率を確認（95%以上が目安）
- [ ] 失敗メールがあれば原因調査・再送
- [ ] バックアップが正常に取得できたことを確認
- [ ] 送信完了報告（必要に応じて）

## 週次メンテナンス

### 毎週月曜日（作業時間: 約10分）

#### チェック項目

```bash
# 1. バックアップ確認
ls -lh backups/*.tar.gz | tail -5

# 最新のバックアップ日付を確認
ls -lt backups/*.tar.gz | head -1

# 2. ログファイルサイズ確認
du -sh logs/
ls -lh logs/app.log

# 3. ディスク容量確認
df -h .
```

#### 実施内容

- [ ] 直近のバックアップが正常に取得されているか確認
- [ ] バックアップファイルが破損していないか（展開テスト）
- [ ] ログファイルが肥大化していないか確認（1GB以上なら対処）
- [ ] ディスク容量に余裕があるか確認（80%以下が目安）

#### 異常時の対応

**バックアップが取得できていない場合:**
```bash
# 最新の送信結果から手動バックアップ
./scripts/backup.sh <送信日>
```

**ログファイルが大きい場合:**
```bash
# ログをローテーション
mv logs/app.log logs/app.log.$(date +%Y%m%d)
gzip logs/app.log.*
```

## 月次メンテナンス

### 毎月1日（作業時間: 約30分）

#### 1. 宛先マスタ更新

```bash
# 宛先マスタをバックアップ
cp data/recipients.xlsx data/recipients_backup_$(date +%Y%m%d).xlsx

# 更新作業
# - 入社者追加
# - 退社者削除
# - メールアドレス変更対応

# 更新後のチェック
npx tsx src/cli/plan.ts --date $(date +%Y-%m-%d)
```

**チェックリスト:**
- [ ] 前月の人事異動を反映
- [ ] 入社者のメールアドレスを追加
- [ ] 退社者を削除
- [ ] メールアドレス変更を反映
- [ ] 重複がないか確認
- [ ] テスト実行で問題ないか確認

#### 2. 古いバックアップ削除

```bash
# 90日以前のバックアップを削除
find backups -name "*.tar.gz" -mtime +90 -ls
find backups -name "*.tar.gz" -mtime +90 -delete

# 削除後の確認
ls -lh backups/ | wc -l
```

**保管期間の目安:**
- 直近3ヶ月: すべて保管
- 3〜6ヶ月: 月次バックアップのみ保管
- 6ヶ月以上: 削除

#### 3. 古い送信結果の整理

```bash
# 3ヶ月以上前の送信結果を圧縮
find output -type d -mtime +90 -exec tar -czf {}.tar.gz {} \;
find output -type d -mtime +90 -exec rm -rf {} \;

# 6ヶ月以上前のexportsを削除（必要に応じて）
find exports -type d -mtime +180 -exec rm -rf {} \;
```

#### 4. システムアップデート確認

```bash
# Node.js / npm のバージョン確認
node -v
npm -v

# 依存パッケージの脆弱性チェック
npm audit

# 必要に応じてアップデート
npm audit fix
```

## 四半期メンテナンス

### 3ヶ月に1回（作業時間: 約1時間）

#### 1. リカバリテスト実施

```bash
# リカバリテスト用ディレクトリを作成
mkdir -p recovery_test

# 最新のバックアップを展開
LATEST_BACKUP=$(ls -t backups/*.tar.gz | head -1)
tar -xzf $LATEST_BACKUP -C recovery_test

# データが正常に復元できるか確認
ls -la recovery_test/

# Excelファイルが開けるか確認
# JSONファイルが読めるか確認
```

**チェックリスト:**
- [ ] バックアップファイルが正常に展開できる
- [ ] 宛先マスタExcelが開ける
- [ ] 送信結果JSONが読める
- [ ] 送信対象Excelが開ける
- [ ] .env の設定が記録されている

#### 2. 運用マニュアル見直し

- [ ] README.md の内容が最新か確認
- [ ] ERROR_HANDLING.md の内容を更新
- [ ] 新しいエラーパターンがあれば追記
- [ ] 運用フローに変更があれば更新

#### 3. パフォーマンス確認

```bash
# 送信速度を確認
cat logs/app.log | grep "send completed" | tail -10

# レート制限が適切か確認
cat logs/app.log | grep "DRY_RUN\|sent" | tail -20
```

## 緊急時の連絡フロー

### エラー発生時

1. **即座に実施**
   - エラーログを確認
   - ERROR_HANDLING.md で対処法を確認
   - 可能であれば即座に修正・再送

2. **報告**
   - システム管理者に連絡
   - エラー内容と対処状況を報告

3. **記録**
   - 発生日時、エラー内容、対処方法を記録
   - 再発防止策を検討
