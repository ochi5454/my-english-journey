## ログイン方法

### Microsoft アカウントでログイン（推奨）

1. ログイン画面で「Microsoftでログイン」ボタンをクリック
2. 会社のMicrosoftアカウントでサインイン
3. 初回のみ、アプリへのアクセス許可を承認

### 管理者アカウントでログイン

1. メールアドレスとパスワードを入力
2. 「管理者でログイン」ボタンをクリック

> **注意**: 管理者アカウントは開発/テスト環境向けです。本番環境ではMicrosoftアカウントを使用してください。

## ファイルのアップロード

### 対応ファイル形式

| 形式 | 拡張子 | 備考 |
|------|--------|------|
| Excel | .xlsx | 推奨 |
| Excel (旧形式) | .xls | 対応 |
| CSV | .csv | UTF-8, Shift-JIS対応 |

### ファイル種別

| ファイルキー | 表示名 | 説明 |
|-------------|--------|------|
| schedule_input | 勤務予定入力 | 勤務予定データ |
| punches | 出退社時刻 | 打刻データ |
| days_items | 日数項目 | 日数関連データ |
| tim_daily | 日次実績 | 日次勤務実績 |
| person_progress | 勤務予定進捗一覧 | 従業員の進捗状況 |
| org_info | 所属情報 | 組織・所属データ |

### アップロード手順

1. 左側のサイドバーからファイル種別を選択
2. ファイルをドラッグ&ドロップ、または「ファイルを選択」をクリック
3. アップロード進捗を確認
   - 経過時間と推定残り時間が表示されます
   - キャンセルする場合は「キャンセル」ボタンをクリック
4. 「アップロード完了」と表示されたら完了

### 重複ファイル検出

同一内容のファイルを再アップロードしようとすると、システムが自動的に検出し、既存のデータを再利用します。これによりストレージと処理時間を節約できます。

### ファイル履歴

過去にアップロードしたファイルの履歴は、データセット管理画面から確認できます。

```
GET /datasets/history/{file_key}
```

## データの確認

### 検索機能

| フィールド | 検索方法 | 例 |
|-----------|---------|-----|
| 従業員名 | 部分一致 | 「山田」で「山田太郎」がヒット |
| 従業員番号 | 前方一致 | 「123」で「12345」がヒット |
| 部署 | 前方一致 | 所属コードで絞り込み |
| 日付範囲 | 期間指定 | 開始日〜終了日 |

### 色分けの意味（残業時間）

| 色 | 残業時間 | 意味 | 対応レベル |
|---|---------|------|----------|
| 青 | 15-20時間 | 通常 | INFO |
| 緑 | 20-30時間 | 社内基準内 | INFO |
| 黄 | 30-45時間 | 社内上限接近 | WARNING |
| オレンジ | 45-60時間 | 法定上限超過 | DANGER |
| 赤 | 60-80時間 | 特別条項上限 | CRITICAL |
| 濃茶 | 80時間以上 | 要即時対応 | CRITICAL |

## 残業アラート

### 36協定アラート機能

システムは自動的に残業時間を監視し、以下の閾値を超えた従業員を検出します：

| レベル | 閾値 | 説明 |
|--------|------|------|
| INFO | 15時間〜 | 監視対象 |
| WARNING | 30時間〜 | 社内上限接近 |
| DANGER | 45時間〜 | 法定上限（労働基準法） |
| CRITICAL | 60時間〜 | 特別条項発動 |

### アラートの確認

```
GET /excel/overtime/alerts?min_level=warning
```

レスポンス例：
```json
{
  "alerts": [
    {
      "employee_id": "12345",
      "employee_name": "山田太郎",
      "department": "営業部",
      "current_hours": 52.5,
      "level": "danger",
      "message": "法定残業上限（45時間）に達しています。"
    }
  ],
  "summary": {
    "total": 10,
    "critical_count": 2,
    "danger_count": 3,
    "warning_count": 5
  }
}
```

### アラート通知

```
POST /notifications/overtime-alerts
Content-Type: application/json

{
  "min_level": "warning",
  "dry_run": true
}
```

> **注意**: `dry_run: true` の場合、実際の通知は送信されません。対象者リストのみ返されます。

## エクスポート

### Excel出力

1. 「Excelダウンロード」ボタンをクリック
2. 所属名称6ごとに別ファイルが生成されます
3. ブラウザのダウンロードフォルダを確認

### 出力ファイルの内容

- **時間外労働_エクスポート_[部署名]_[日時].xlsx**
  - シート1: データ一覧（色分け付き）
  - シート2: 残業時間詳細

### CSV出力

大量データの場合はCSV形式でエクスポートできます：

```
POST /datasets/{dataset_id}/export
```

## APIキー（開発者向け）

外部システムとの連携には、APIキー認証を使用します。

### APIキーの作成（管理者のみ）

```
POST /api-keys/
Content-Type: application/json

{
  "name": "外部システム連携用",
  "scopes": ["read", "write"],
  "expires_in_days": 365
}
```

レスポンス例：
```json
{
  "id": 1,
  "name": "外部システム連携用",
  "api_key": "ragt_xxxxxxxxxxxxxxxxxxxxx",
  "message": "APIキーが作成されました。このキーは一度しか表示されません。"
}
```

> **重要**: 返されるAPIキーは一度しか表示されません。安全に保管してください。

### APIキーの使用

リクエストヘッダーにAPIキーを含めます：

```
X-API-Key: ragt_xxxxxxxxxxxxxxxxxxxxx
```

### APIキーの無効化

```
DELETE /api-keys/{key_id}
```

## よくある質問

### Q: アップロードに時間がかかります

A: ファイルサイズや行数によって処理時間が異なります。7000行程度で30秒〜3分程度かかることがあります。

### Q: 前回アップロードしたデータが消えました

A: ブラウザのキャッシュをクリアすると、一時保存されたデータが削除される場合があります。サーバー上のデータは保持されていますので、データセット一覧から確認してください。

### Q: 同じファイルをアップロードしようとしたら既存データが返されました

A: システムの重複ファイル検出機能です。同一内容のファイルが既にアップロードされている場合、既存のデータを再利用します。新しいデータとして処理したい場合は、ファイル内容を変更してください。

### Q: 特定の従業員だけエクスポートできますか？

A: 検索機能で絞り込んだ状態でエクスポートすると、表示中のデータのみが出力されます。

### Q: CSVファイルが文字化けします

A: システムはUTF-8, Shift-JIS, CP932, EUC-JPのエンコーディングを自動検出します。それでも問題がある場合は、UTF-8（BOM付き）で保存し直してください。

### Q: APIキーを紛失しました

A: セキュリティ上の理由から、APIキーの再表示はできません。新しいAPIキーを作成し、古いキーは無効化してください。
