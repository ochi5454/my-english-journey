# アーキテクチャ比較 - All-in-One vs 分離デプロイ

このドキュメントでは、**分離デプロイアーキテクチャ**と **All-in-One コンテナアーキテクチャ**の比較を説明します。

**作成日**: 2026年2月13日
**対象システム**: AI Mail
**採用予定**: All-in-One アーキテクチャ (Option C)

---

## エグゼクティブサマリー

### AI Mail システムの採用アーキテクチャ

| 環境 | アーキテクチャ | ステータス |
|------|--------------|----------|
| **ローカル開発（分離）** | 分離コンテナ（docker-compose） | ✅ 実装済み |
| **ローカル開発（ハイブリッド）** | PostgreSQL: Docker / FE+BE: ローカル | ✅ 実装済み |
| **Azure 本番（All-in-One）** | All-in-One Container Apps | ⏳ 準備中 |

### All-in-One を採用する理由

- ✅ **シンプルな構成**（1つのコンテナのみ）
- ✅ **低コスト**（複数のマネージドサービス不要）
- ✅ **簡単なデプロイ**（1コマンドで完了）
- ✅ **開発・本番環境の整合性**（同じ構成）

---

## アーキテクチャ比較

### 1. All-in-One コンテナアーキテクチャ ✅ 採用予定

#### 構成
```
┌─────────────────────────────────────────┐
│   Docker Container (~2.5GB)             │
│  ┌────────────────────────────────────┐ │
│  │  Next.js Frontend (Port 3000)      │ │
│  │  ├─ App Router (SSR)               │ │
│  │  └─ API Proxy → Backend            │ │
│  └────────────────────────────────────┘ │
│  ┌────────────────────────────────────┐ │
│  │  FastAPI Backend (Port 8000)       │ │
│  │  ├─ Python 3.11                    │ │
│  │  ├─ LangChain                      │ │
│  │  └─ OpenAI API 統合                │ │
│  └────────────────────────────────────┘ │
│  ┌────────────────────────────────────┐ │
│  │  PostgreSQL 16 (Port 5432)         │ │
│  │  └─ Database Files (Volume)        │ │
│  └────────────────────────────────────┘ │
│                                         │
│  Managed by: supervisord                │
└─────────────────────────────────────────┘
```

#### デプロイフロー
1. ソースコード変更（フロントエンドまたはバックエンド）
2. Docker イメージを再ビルド（**10-15分**）
3. Azure Container Registry にプッシュ
4. Container Apps にデプロイ
5. 全体起動（Next.js + FastAPI + PostgreSQL）

#### メリット
- ✅ シンプルな構成（1つのコンテナ）
- ✅ 初回デプロイが簡単
- ✅ ローカル開発環境との整合性
- ✅ 低コスト（複数のマネージドサービス不要）
- ✅ ネットワーク遅延ゼロ（内部通信）

#### デメリット
- ❌ **部分的な更新ができない**: フロントエンドだけ変更してもバックエンドとDBも再ビルド
- ❌ **スケーリングの柔軟性がない**: フロントエンドとバックエンドを独立してスケールできない
- ❌ **データ永続性の注意**: コンテナ再起動時のデータ保護が必要

### 2. 分離デプロイアーキテクチャ（参考）

#### 構成
```
┌──────────────────────────────────────────────────────────┐
│          インターネット (HTTPS)                           │
└──────────────────┬───────────────────────────────────────┘
                   │
                   ↓
┌──────────────────────────────────────────────────────────┐
│      Microsoft Entra ID (認証)                           │
└──────────────────┬───────────────────────────────────────┘
                   │
                   ↓
┌──────────────────────────────────────────────────────────┐
│               Container Apps Environment                 │
│  ┌─────────────────────┐  ┌────────────────────────┐   │
│  │  Frontend Container │  │  Backend Container     │   │
│  │  (Next.js)          │  │  (FastAPI)             │   │
│  │  Port: 3000         │  │  Port: 8000            │   │
│  │  Min Replicas: 0    │  │  Min Replicas: 0       │   │
│  │  Max Replicas: 3    │  │  Max Replicas: 5       │   │
│  │  CPU: 0.5, RAM: 1GB │  │  CPU: 1.0, RAM: 2GB    │   │
│  │  Size: ~500MB       │  │  Size: ~1.5GB          │   │
│  │  Deploy: 2-3分      │  │  Deploy: 5-7分         │   │
│  └─────────┬───────────┘  └────────┬───────────────┘   │
│            │ /api/                  │                    │
│            └────────────────────────┘                    │
└──────────────────────────────────────────────────────────┘
                           │
                           ↓
┌──────────────────────────────────────────────────────────┐
│           Azure PostgreSQL Flexible Server               │
│           Tier: Burstable Standard_B1ms                  │
│           Storage: 32GB                                  │
│           Backup: 7 days                                 │
│           ✅ 完全に保護されたデータ                       │
└──────────────────────────────────────────────────────────┘
```

#### メリット
- ✅ **デプロイ時間が短い**: 2-7分（部分更新）
- ✅ **部分的な更新が可能**: 変更した部分だけデプロイ
- ✅ **独立したスケーリング**: フロントエンドとバックエンドを個別にスケール
- ✅ **データベースの完全な保護**: マネージドDB使用

#### デメリット
- ⚠️ 構成が複雑（3コンポーネント）
- ⚠️ コスト増加（マネージドDBの料金 ¥15,000/月〜）
- ⚠️ 初回セットアップに時間が必要

---

## ⚠️ 重要: データベースの永続性

**All-in-One アーキテクチャと分離デプロイの最大の違い**:

| 項目 | All-in-One | 分離デプロイ |
|------|---------------------------|---------------------------|
| **データベースの場所** | コンテナ内部 | 外部マネージドサービス |
| **デプロイ時のデータ** | ⚠️ 注意が必要（ボリュームマウント推奨） | ✅ **完全に保護される** |
| **フロントエンド更新** | DB も一緒に再起動 | **DB は影響を受けない** |
| **バックエンド更新** | DB も一緒に再起動 | **DB は影響を受けない** |
| **月額コスト** | ¥2,600-4,100 | ¥22,500-30,000 |

### All-in-One でのデータ保護戦略

AI Mail システムでは、All-in-One アーキテクチャを採用しつつ、以下の方法でデータを保護します：

1. **Azure Files ボリュームマウント**: PostgreSQL データを外部ストレージに保存
2. **定期バックアップ**: データベースダンプを Azure Blob Storage に保存
3. **ゼロダウンタイムデプロイ**: ローリングアップデートでデータ損失を防止

```
┌─────────────────────────────────────────┐
│   Container Apps                        │
│  ┌────────────────────────────────────┐ │
│  │  PostgreSQL                        │ │
│  │    ↓                               │ │
│  │  /var/lib/postgresql/data          │ │
│  └─────────┬──────────────────────────┘ │
│            │ Volume Mount               │
└────────────┼────────────────────────────┘
             ↓
┌─────────────────────────────────────────┐
│  Azure Files (永続ストレージ)           │
│  ✅ コンテナ再起動でもデータ保持        │
└─────────────────────────────────────────┘
```

## コスト分析

### All-in-One（採用予定）

```
Container Apps: ¥1,500-2,500/月
- CPU: 1 vCPU
- Memory: 2GB
- Storage: Azure Files (~¥500/月)
- Min Replicas: 1

Log Analytics: ¥500-1,000/月
Container Registry: ¥600/月

合計: ¥2,600-4,100/月
```

### 分離デプロイ（参考）

```
Frontend Container Apps: ¥2,500-5,000/月
- CPU: 0.5 vCPU
- Memory: 1GB
- Min Replicas: 0 (Cold Start)

Backend Container Apps: ¥5,000-10,000/月
- CPU: 1 vCPU
- Memory: 2GB
- Min Replicas: 0 (Cold Start)

Azure PostgreSQL Flexible Server: ¥15,000/月
- Burstable tier: Standard_B1ms
- Storage: 32GB

合計: ¥22,500-30,000/月
```

### コスト比較

| 項目 | All-in-One | 分離デプロイ | 差額 |
|------|-----------|-------------|------|
| 月額コスト | ¥2,600-4,100 | ¥22,500-30,000 | **¥19,900-25,900 節約** |
| 年間コスト | ¥31,200-49,200 | ¥270,000-360,000 | **¥238,800-310,800 節約** |

## 使い分けの推奨

### All-in-One アーキテクチャが適している場合 ✅

- ✅ **AI Mail システム**（中小規模、コスト重視）
- ✅ テスト環境・開発環境
- ✅ プロトタイプ・PoC
- ✅ デモ環境
- ✅ シンプルな構成を優先する場合
- ✅ 予算制約がある場合

### 分離デプロイアーキテクチャが適している場合

- 大規模システム（高トラフィック）
- データ永続性が最重要な場合
- 頻繁なデプロイが必要な場合（1日10回以上）
- 独立したスケーリングが必要な場合
- エンタープライズ向け（SLA 99.99%必須）

---

## 結論

AI Mail システムでは、**All-in-One アーキテクチャ (Option C: Container Apps)** を採用予定です。

**採用理由**:
1. ✅ **コスト効率**: 月額 ¥2,600-4,100 vs 分離デプロイの ¥22,500-30,000
2. ✅ **シンプルな構成**: 1つのコンテナで完結
3. ✅ **十分な機能**: 自動スケーリング、ゼロダウンタイムデプロイ対応
4. ✅ **開発効率**: ローカル環境との整合性

**データ保護対策**:
- Azure Files ボリュームマウントでデータ永続化
- 定期バックアップの実装
- ローリングアップデートによるゼロダウンタイムデプロイ
